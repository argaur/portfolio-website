What it is

Overview

A spec compiler with a scorecard attached. You give it the rules an agent should follow. It writes a test suite from those rules. The scorecard reports spec coverage and spec conformance, not a pass rate.

The code name is agent-proving-ground. RuleCard is the public name. It is hosted with sign-in and has no billing. The public page at rulecard.gauravg.dev walks through one example run, with no sign-in.

Tests from intent,
not from behaviour.

01 · The idea

Most agent tests are written after watching what the agent does. That checks the agent against itself. RuleCard writes tests from what the owner said the agent must do, so a gap in the rules shows up as a gap in the tests.

Every test carries the number of the rule it came from. A score with no rule number is treated as a bug. The first thing the report shows is the list of rules with no test.

One open risk. The method needs a written spec with numbered rules to exist already. Getting a clear spec out of a team is the real work, and I have not shown it can be done cheaply.
